# BladePath — журнал разработки, инвентарь задач и состояние выпуска

**Создан:** 2026-11-02. **Основная рабочая ветка:** `bladepath-development`. **Точная опись 604 уже существующих файлов:** [REPOSITORY_INVENTORY.md](REPOSITORY_INVENTORY.md).  
Этот документ — обязательная память для ежечасного задания. Он **не заменяет** проверку GitHub и не гарантирует, что существующий файл использован или работает.

## ОБЯЗАТЕЛЬНЫЙ протокол каждого запуска

1. **Сначала читать этот документ целиком** и `docs/REPOSITORY_INVENTORY.md`; проверить текущие `main`, `bladepath-development`, `apk-build`, `apk-latest`, GitHub Actions и фактические пути файлов. Проверять не только совпадение имени, но и аналог по назначению. Нельзя воссоздавать существующий арт или модель.
2. Искать существующий `BP-###` по смыслу. Работать в порядке **P0 ошибки из скриншотов → заблокированные уже подготовленные ресурсы → P1 доработка существующего → P2 новые ассеты**. Уточнения пользователя о приоритетах имеют преимущество.
3. Вносить рабочие исправления **в `bladepath-development`**; проходить лёгкий `BladePath Preflight (No APK)` (он не компилирует Unity). Готовый пакет переводить в `apk-build` **один раз после завершения предыдущей сборки**. Коммиты в `main` не должны автоматически запускать Android; не создавать 33 отменённых сборки.
4. **После КАЖДОГО изменения** обновлять запись задачи: что именно изменено, реальные пути, коммит, проверка, статус, оставшиеся действия. **Перед завершением каждого часового запуска обязательно записывать в этот файл строку хронологии** и при необходимости обновлять очередь. Если прогресса нет, указать блокер/результат проверки, не имитировать работу.
5. `TODO` — не сделано; `IN_PROGRESS` — начато; `FILE_PRESENT` — реальный ресурс есть в GitHub, применение не доказано; `CODE_READY` — исходник интегрирован; `PREFLIGHT_OK` — быстрые проверки успешно завершились; `APK_PENDING` — нужен APK с соответствующим SHA; `APK_VERIFIED` — APK этого SHA успешен **и** пользовательская проблема подтверждённо устранена скриншотом/тестом; `BLOCKED` — нужна внешняя модель/доступ; `REGRESSION` — проблема воспроизведена.
6. Запрещено помечать `APK_VERIFIED` по результатам старого SHA. Успешный CI preflight — **не** компиляция Unity. Наличие `.jpg` в GitHub — **не** доказательство соответствия утверждённому макету. При сомнениях фиксировать неопределённость.
7. При создании модели из Meshy сначала сверять список `.fbx/.obj/.glb` и `EnvironmentBuilder.cs`; для готовых объектов не запрашивать дубликаты. Новые модели — отдельные ресурсы с нормальной сеткой и PBR, а не набор примитивов.
8. Если журнал или инвентарь отсутствует/не читается, **не выполнять новую генерацию наугад**; восстановить/проверить записи и только потом продолжать.

## Зарегистрированные планы / ограничения

- Основной проект — **Unity**, Android, арена с боями катаной и карта-путешествие. Не переводить на другой движок.
- Карта: три региона (`map_0..2`), мосты обязательны, нельзя срезать по прямой сквозь реки/утёсы; визуально понятный доступный маршрут, устойчивый маркер всадника.
- «Начать игру»: последовательный выбор сложности и игрока. **Три варианта каждого уже есть**; не рисовать заново на каждом запуске.
- Два разных набора экранов, показанных пользователем, — макеты для соответствия общей стилистике, а не повод обнулять текущие ресурсы. Утверждённые лица и имена должны сохраняться.
- Бой: естественные движения с катаной и двуручный хват, читаемые HUD, удар/парирование, реалистичная кровь без «наследства» предыдущего боя. Статус после быстрых CI — не итог на устройстве.
- Источники внешних моделей Meshy обрабатываются **по одной**; уже существующие `jizo.obj`, `komainu.obj`, `bamboo_fence.obj` **не повторять**. Фонарь/тётин/стену не считать готовыми до получения GLB/FBX.
- Для скриншотов и пользовательских замечаний всегда создавать или обновлять задачу `BP-###`, а не начинать случайную новую графику.
- `docs/generated-visual-pack-01.md` и `docs/generated-visual-pack-02.md` — исторические описания. Проверять **реальные** директории и SHA, не считать архив в чате автоматически встроенным.
- `README.md` описывает раннее состояние проекта и может быть устаревшим; актуальны этот журнал и код.
