# Путь клинка — Этап 1 (минимальный прототип)

Версия Unity в CI: **6000.0.36f1** (на ней GameCI измерил активацию Personal-лицензии; 6.0 LTS поддерживается до октября 2026, переход на 6.3 LTS — смена одной строки `UNITY_VERSION` в workflow, но на 6.3 путь не проверялся).
Статус проверки: код типизирован компилятором C# против заглушек Unity API; в самом Unity на момент написания не запускался.

## Визуал (текстуры и модели)
- Текстуры (броня, ткань, сталь, камень, лак, плоть) генерирует `tools/gen_textures.py` → `Assets/_Project/Art/Textures`. Палитра взята с концепт-арта. Запуск: `python3 tools/gen_textures.py`.
- Материалы создаёт `Editor/VisualMaterials.cs` (шейдер Standard, нормал-мапы). Бойцов «одевает» `Editor/CharacterVisuals.cs` (герой: волосы, борода, наплечники, пояс, ножны; враг: шлем с рогами, лохмотья, 6 щупалец с пастями — анимация `Visual/TentacleWiggle.cs`). Окружение: `Editor/EnvironmentBuilder.cs` (ночь, туман, луна, тории, пагода, жаровни с мерцанием, лепестки).
- Это визуал из примитивов, не финальные модели: у него НЕТ скелетной анимации и коллайдеров. Зоны поражения остались прежними. Щупальца пока декоративные.
- Подсветка попаданий идёт через emission (`Fighter/BodyZone.cs`), поэтому на материалах зон тела включается `_EMISSION` заранее.

## Облачная сборка на Codemagic (если GitHub недоступен)
Файл `codemagic.yaml` в корне. Нужны: репозиторий на GitLab, приложение в Codemagic, группа переменных `unity` с `UNITY_EMAIL` и `UNITY_PASSWORD` (Secure). Сборка идёт на macOS M2 (бесплатный план: 500 минут в месяц). APK и лог Unity лежат в артефактах сборки.
Версию Unity берём ту, что предустановлена на машине Codemagic, поэтому `ProjectSettings/ProjectVersion.txt` перед сборкой удаляется.

## Как получить APK без ПК (GitHub Actions + GameCI)
Workflow `.github/workflows/build-android.yml` собирает debug-APK в облаке (Unity 6000.0.36f1, IL2CPP, ARM64).
1. В репозитории → Settings → Secrets and variables → Actions добавь `UNITY_EMAIL` и `UNITY_PASSWORD` (отдельный аккаунт Unity Personal, без 2FA).
2. Вкладка Actions → **Build Android APK** → Run workflow (запускается и сам при пуше в `main`).
3. Первая сборка долгая (скачивание образа Unity ~10+ ГБ, импорт проекта). Дальше быстрее за счёт кэша `Library`.
4. Готовый APK: открой завершённый запуск → внизу **Artifacts** → `BladePath-Android-APK` (zip, внутри `BladePath.apk`). Рядом артефакт `build-log` с полным логом Unity.
5. Установка на телефон: распакуй zip, тапни APK, разреши установку из неизвестных источников.
Если сборка красная — открой шаг **Build APK** или скачай `build-log`: причина будет в логе.

Сцена в репозитории не хранится: `BuildScript` создаёт её из кода (`PrototypeSceneBuilder`) прямо перед сборкой.

## Что в сборке
Две сцены: **MainMenu** (индекс 0) → **Prototype_Stage1**. Обе создаются из кода перед сборкой.
- Меню: ролик 852x480 целиком (панель запечена в видео) + невидимые зоны нажатия. New Game → бой, Continue → заглушка, Settings → переключатель анимации, Exit → выход. Видео лежит в `Assets/StreamingAssets/menu_bg.mp4`, постеры — `Assets/_Project/Art`.
- Бой: возврат в меню — кнопка «Меню» или Esc.

## Атаки и движение
| Атака | Кнопка / клавиша | Куда достаёт (расчёт, не замер) |
|---|---|---|
| Сверху (рубящий по диагонали) | СВЕРХУ / J | голова + торс на ≤1,2 м |
| Снизу (вверх по диагонали, с приседанием руки) | СНИЗУ / K | торс на ≤1,2 м, ещё и ноги на ≤1,0 м |
| По ногам (низкий горизонтальный рез) | ПО НОГАМ / N | ноги на ≤1,1 м |
| Удар в прыжке (рубящий в воздухе, бросок вперёд) | любая рубящая в воздухе | голова + торс на ≤1,2 м при высоте ≤0,3 м, до 1,0 м при ≤0,5 м |
| Энергошар (дальняя) | ШАР / M | летит по прямой 7 м/с, замах 0,35 с |
Прыжок: ПРЫЖОК / W. Движение (A/D, ←/→) разрешено во время удара, скорость ×0,8 (`attackMoveMultiplier` у FighterController).
Враг: «Враг: <тип> ▸» (E) выбирает тип удара, «ВРАГ БЬЁТ» (L) запускает. Сброс — R.
Кнопки на экране читаются по касаниям напрямую (мультитач): можно держать «вперёд» и бить другой рукой.

## Как запустить на ПК (если появится)
Создай 3D-проект Unity, скопируй `Assets` целиком, выбери **Tools → Blade Path → Build Main Menu Scene** и **Build Stage 1 Prototype Scene**, открой MainMenu и нажми Play.
`F1` — вкл/выкл отладку.
Старый Input Manager используется намеренно (этап 1 не зависит от пакета Input System). Отладочные линии рисуются мешем, поэтому видны и в APK, и без включения Gizmos.

## Как проверить попадание и промах
- Сцена стартует с дистанцией 2,0 м. Ударь сразу → в журнале **ПРОМАХ**.
- Подойди (D) примерно до 1,2 м между осями и ударь → **ПОПАДАНИЕ → Enemy.Torso / Enemy.Head**, зона вспыхивает красным.
- Ближе 1,1 м: голова и торс. На ≥1,3 м — промах.
  (Расчёт по геометрии, не замер в Unity: см. «Ограничения».)
- Оранжевая линия — траектория кончика, голубые — остальные точки клинка; красная сфера — контакт, жёлтая линия — нормаль, пурпурная — направление клинка (зелёная — скользящий контакт).
- В строке состояния: `подшагов/кадр` и предупреждение, если подшагов не хватило (возможны пропуски).

## Архитектура обнаружения (раздел 26.4–26.5 ТЗ)
Клинок — НЕ Rigidbody и НЕ Unity-коллайдер. Это отрезок `bladeRoot → +Z × bladeLength` с контрольными точками (по умолчанию 6).
Каждый кадр в окне контакта (фазы Strike + FollowThrough) `BladeTrajectorySampler`:
1. берёт позу клинка прошлого и текущего кадра;
2. режет движение на подшаги: по `maxAngleStepDeg` (3°) и `maxLinearStep` (6 см), максимум 16;
3. позу между кадрами восстанавливает Lerp(позиция) + Slerp(вращение) — поэтому учитывается поворот, а не только перенос;
4. для каждой контрольной точки делает `SphereCast` между соседними подшагами (радиус = `bladeRadius`);
5. отдельно `OverlapSphere`, потому что каст не видит коллайдер, внутри которого сфера уже стоит;
6. контакты подшага сортирует по расстоянию, каждая зона регистрируется **один раз за удар**.
Тела — `CapsuleCollider`/`SphereCollider` на отдельных объектах-зонах (`BodyZone`), без Rigidbody.

## Риски и ограничения (26.6)
- **Не запускалось в Unity.** Возможны ошибки, которых компилятор на заглушках не видит (ссылки, порядок исполнения, нюансы версий API).
- Слерп между позами внутри подшага — линейное приближение вращения. Для очень быстрых поворотов уменьши `maxAngleStepDeg` (дороже по CPU).
- Закрытие окна контакта и конец кадра: хвост движения в кадре смены фазы не проверяется (до ~1 кадра в конце проводки).
- Тест «зон достижимости» (промах ≥1,3 м, попадание ≤1,2 м) посчитан отдельной математикой, а не измерен в Unity. Если в сцене цифры другие — это баг геометрии/сэмплера, смотри отладку.
- Один удар задевает несколько зон (голова, затем торс) — клинок после контакта не останавливается и не отклоняется. Блоки и столкновения клинков — Этап 2. Урон и реакции — Этап 4.
- Руки и ноги этим единственным ударом не достаются (рубящий сверху по центру) — ожидаемо для одной атаки.
- Дистанция, на которой достаётся тело, зависит от `bladeLength`, смещения руки и позы: числа в этом README — для значений по умолчанию.
- Физическая частота (Fixed Timestep) не используется для проверки; всё в `LateUpdate` по кадру. Если понадобится детерминизм/сеть — переносить в FixedUpdate отдельно.
- IMGUI-кнопки и журнал — для отладки, не боевой интерфейс.
